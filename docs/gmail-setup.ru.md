# Gmail для SupportOps AI

Адрес отправителя и поддержки: **info.xenonimus@gmail.com**.

## Что уже подготовлено

- В локальном игнорируемом `.env` настроены Gmail SMTP, адрес отправителя, Reply-To и контакт оператора. Файл имеет права доступа 600; пароль не добавлен и не выводился.
- Gmail использует `smtp.gmail.com:587` с STARTTLS и проверкой сертификата. Для альтернативного режима 465 предусмотрены `SMTP_SSL=true` и `SMTP_STARTTLS=false`.
- Отсутствие SMTP-пароля, несовместимые TLS-настройки и небезопасный публичный URL в production не считаются готовой почтой.
- Письма подтверждения и восстановления используют одноразовые ссылки. Неудачная повторная отправка не аннулирует предыдущую ссылку. Использование одной ссылки отзывает остальные того же назначения; восстановление пароля также завершает сессии пользователя.
- Ошибки SMTP записываются техническим кодом без пароля, содержимого письма, получателя и полного ответа провайдера.
- Есть `GET /api/email/status` для owner/admin и локальная команда диагностики. Ни один из этих способов не отправляет тестовое письмо.
- Лимит $5, демо-режим и отметки будущего запуска покупки сохранены.

SMTP используется для исходящих писем приложения. Чтение входящих писем этого Gmail-ящика и превращение их в заявки пока не подключены. Заявки доступны через публичные формы, inbound API и внутреннее создание.

## Что осталось сделать владельцу Gmail

1. Войди в Google-аккаунт **info.xenonimus@gmail.com** и включи двухэтапную аутентификацию.
2. Открой [Пароли приложений](https://myaccount.google.com/apppasswords) и создай отдельный пароль для SupportOps AI. Вариант может быть недоступен из-за настроек аккаунта. Для текущего SMTP-адаптера нужен пароль приложения; обычный пароль Google в проект не вводи. Если Google не предоставляет эту возможность, потребуется отдельное подключение OAuth либо другой SMTP-провайдер — оно сейчас не реализовано. [Официальная справка Google](https://support.google.com/mail/answer/185833?hl=ru).
3. Открой локальный `.env` редактором и заполни **только у себя**:

```dotenv
SMTP_PASSWORD=пароль_приложения_без_разделительных_пробелов
```

Не присылай пароль в чат, не вставляй в команды shell и не коммить. На сервере используй Secrets Manager; в Terraform передаётся только ARN секрета.

4. В активированном `.venv` выполни проверку настроек:

```bash
python -m scripts.check_email
```

Пока пароль не добавлен, ожидается `ready: false` и `missing: ["SMTP_PASSWORD"]`. После добавления `ready: true` означает полноту конфигурации, а не доказанную доставку.

5. Проверь соединение и аутентификацию:

```bash
python -m scripts.check_email --connect
```

Команда делает TLS/LOGIN/NOOP и **не отправляет письмо**. `smtp_connected` означает успешную проверку подключения. `smtp_authentication_failed` требует проверки аккаунта и пароля приложения. В выводе не будет пароля или полного ответа сервера.

6. Перезапусти API и index-worker после изменения окружения. Для публичного запуска укажи `APP_ENV=production` и свой HTTPS-домен в `PUBLIC_BASE_URL`: ссылки из письма должны открываться у получателей, а не вести на localhost.
7. В интерфейсе самостоятельно зарегистрируй тестовый аккаунт со своим доступным адресом. Проверь письмо, спам-папку и работу ссылки; затем проверь восстановление пароля. Переход по ссылке подтверждения — отдельная пользовательская проверка, не результат SMTP-диагностики.

Настройки SMTP соответствуют [справке Gmail](https://support.google.com/mail/answer/7104828?hl=ru). Лимиты отправки и доступность паролей приложений определяет Google; текущая настройка не является сервисом массовых рассылок.

## Будущее уведомление о покупке

Пользователи с исчерпанным бюджетом или кнопкой `Email me at launch` уже отмечаются в `demo_accounts`. Команда `scripts.demo_waitlist` экспортирует подтверждённые ожидающие адреса и ничего не отправляет. Массовая рассылка при запуске покупки пока не включена, дата отправки не выставляется заранее.

Письма подтверждения/восстановления выполняются фоновыми задачами процесса API. Постоянной почтовой очереди и автоматических повторов SMTP пока нет; после сбоя можно запросить письмо повторно с учётом ограничения частоты.
