# Подключение реальных API — текущая демо-версия

Код уже поддерживает OpenAI Responses API, embeddings, SMTP и Turnstile. Реальный OpenAI-вызов был проверен на вымышленных данных. Для собственного публичного запуска нужны твои аккаунты и серверные настройки. Stripe сейчас подключать не нужно: тарифы скрыты, checkout, portal и payment webhooks заблокированы при `DEMO_RELEASE=true`.

## 1. Подготовить окружение и сохранить демо-режим

Открой терминал в корне проекта. Если `.env` ещё нет, скопируй `.env.example` в `.env`; существующий файл не перезаписывай. Заполни:

```dotenv
DEMO_RELEASE=true
DEMO_AI_BUDGET_USD=5
MODEL_PROVIDER=openai
EMBEDDING_PROVIDER=openai
```

Лимит — один раз на аккаунт, суммарно по всем компаниям. Смена рабочего пространства, месяц или возраст регистрации его не сбрасывают. В лимит входят индексация, поисковые embeddings, шаги агента и отдельная проверка ответа. Ручные функции не имеют прежних тарифных ограничений по местам, заявкам и объёму знаний; остаются технические ограничения размера загрузки, прав доступа и частоты запросов.

## 2. Подключить OpenAI

1. Войди в [OpenAI Platform](https://platform.openai.com/), создай проект для SupportOps и настрой оплату API.
2. Создай серверный API key для проекта. Не отправляй его в чат и не вставляй во frontend/Git. Сохрани в локальном игнорируемом `.env`; на сервере — в Secrets Manager/секретах окружения. Для staging и production используй отдельные проекты/ключи.
3. Заполни конфигурацию приложения:

```dotenv
OPENAI_API_KEY=твой_секретный_ключ
OPENAI_BASE_URL=https://api.openai.com/v1
AGENT_MODEL=gpt-5.4-mini
VERIFIER_MODEL=gpt-5.4-mini
EMBEDDING_MODEL=text-embedding-3-large
MODEL_INPUT_USD_PER_MILLION=0.75
MODEL_OUTPUT_USD_PER_MILLION=4.50
VERIFIER_INPUT_USD_PER_MILLION=0.75
VERIFIER_OUTPUT_USD_PER_MILLION=4.50
EMBEDDING_INPUT_USD_PER_MILLION=0.13
```

Это текущие настройки проекта, а не неизменная цена провайдера. Перед запуском проверь доступ своего API-проекта к этим моделям и их цены. При замене моделей обнови ставки; при замене embedding-модели переиндексируй документы.

4. Настрой уведомления о расходах в OpenAI и контролируй фактический биллинг. Приложение ограничивает расходы по токенам и настроенным ставкам; итоговые счета провайдера остаются источником истины. Не рассчитывай, что уведомление провайдера само остановит расходы.

Официальные инструкции: [быстрый старт OpenAI](https://developers.openai.com/api/docs/quickstart), [ключи и production](https://developers.openai.com/api/docs/guides/production-best-practices), [цены](https://developers.openai.com/api/docs/pricing).

## 3. Применить миграции и проверить реальные модели локально

Сделай согласованную копию приложения и checkpoint-БД. Затем в активированном `.venv`:

```bash
docker compose --env-file /dev/null -f compose.qdrant.yaml up -d
python -m scripts.migrate
python -m scripts.live_acceptance
```

Вторая команда делает реальные платные вызовы на вымышленных данных с ограниченным бюджетом $0.20; не запускай её циклически. В отчёте должен быть путь: индексация → поиск инструментом → ответ → отдельная проверка → человеческое подтверждение. Обычные `pytest` используют контролируемые ответы и не расходуют OpenAI.

Запуск приложения:

```bash
python -m scripts.dev
```

В отдельном терминале для восстановления фоновых задач после прерываний:

```bash
python -m scripts.index_worker
```

Открой `http://127.0.0.1:8010`. Создай обычную бизнес-компанию, загрузи короткий регламент и дождись `Semantic index ready`. Sample workspace использует вымышленные данные и не вызывает платные модели.

## 4. Подключить почту

Для этого проекта выбран **info.xenonimus@gmail.com**. Gmail-профиль уже сохранён локально, остаётся добавить пароль приложения. Актуальные команды и проверка: [Gmail setup](gmail-setup.ru.md).

Выбери SMTP-сервис, создай/подтверди адрес отправителя и возьми SMTP host, порт, имя пользователя и пароль из его кабинета. Приложение использует STARTTLS, например порт 587, если он поддерживается твоим провайдером:

```dotenv
SMTP_HOST=SMTP_адрес_провайдера
SMTP_PORT=587
SMTP_USER=SMTP_имя
SMTP_PASSWORD=SMTP_пароль
SMTP_FROM=SupportOps AI <hello@твой-домен>
SMTP_STARTTLS=true
REQUIRE_VERIFIED_EMAIL=true
PUBLIC_BASE_URL=https://твой-домен
```

Если используешь Amazon SES, SMTP credentials отличаются от AWS access keys; нужны SMTP endpoint выбранного региона, TLS и подтверждённый отправитель. Следуй [официальной инструкции SES SMTP](https://docs.aws.amazon.com/ses/latest/dg/send-email-smtp.html). Учитывай текущие ограничения отправки своего аккаунта.

Перезапусти приложение и проверь со своим ящиком: регистрацию, получение verification link, подтверждение email и восстановление пароля. В production неподтверждённый email не открывает платные AI-операции.

Письмо о появлении покупки **пока не отправляется автоматически**: проект записывает получателя для будущего запуска. Когда возможность покупки будет готова, оператор должен подготовить письмо и отправить его по этому списку через настроенный сервис.

## 5. Подключить защиту регистрации и форм

В Cloudflare создай Turnstile widget для своего домена. В приложении уже есть виджет и серверная проверка токена; нужно указать:

```dotenv
TURNSTILE_SITE_KEY=публичный_sitekey
TURNSTILE_SECRET_KEY=секретный_ключ
```

Site key показывается браузеру, secret key остаётся на сервере. Разреши фактический hostname staging/production. Проверь регистрацию и публичную форму на своём сайте. [Настройка Turnstile](https://developers.cloudflare.com/turnstile/get-started/).

## 6. Подключить сервер и PostgreSQL

Для публичной демо-версии задай `APP_ENV=production`, HTTPS-домен в `PUBLIC_BASE_URL`, PostgreSQL для бизнес-данных, отдельный Qdrant для векторов и постоянное хранение checkpoints. API и index-worker должны использовать одинаковую БД и настройки моделей.

Для AWS уже подготовлен Terraform: сертификат ACM, ALB, Fargate, RDS, Secrets Manager и deployment workflow описаны в [deployment.md](deployment.md). Укажи ARN серверного OpenAI-ключа в `llm_secret_arn`, SMTP/Turnstile secret ARNs и публичные настройки. Текущая AWS-конфигурация явно сохраняет демо-режим и лимит $5. Не включай Stripe и не меняй `DEMO_RELEASE` для этого запуска.

Сначала staging: проверь ресурсы/стоимость, миграцию и резервное восстановление. Для первого deployment есть `bootstrap=true` с проверкой страницы/БД; после регистрации подтверждённого тестового аккаунта задай `SMOKE_EMAIL`/`SMOKE_PASSWORD` и выполни обычную полную приёмку с `bootstrap=false`. В этом чате push/apply/deploy не выполняются.

## 7. Подключить реальные источники заявок

1. Создай тип заявки в `Request types`.
2. Для формы выбери публичную видимость, затем в `Request sources` создай форму и размести ссылку на своём сайте.
3. Для CRM/сайта создай API connection. Скопируй показанный один раз Bearer token в секреты интеграции.
4. Настрой на стороне своей системы POST на URL созданного подключения. В `Request sources` есть готовый curl-пример. Передавай `customer`, `subject`, `message`, при необходимости `email`, и стабильный `external_id` для защиты от дублей.
5. Повтори отправку с тем же `external_id`: повтор не должен создавать вторую заявку. Отзови тестовый токен и проверь отказ доступа.

Входящий API создаёт заявки, но не запускает платный AI автоматически. Нативные Gmail/Outlook/мессенджер-коннекторы ещё не реализованы: выбранный сервис нужно связать адаптером с inbound API. Автоматической отправки ответов также нет.

## 8. Проверить лимит и будущую рассылку

На странице `AI usage` видны использованная сумма, текущий резерв и остаток. После $5 платные операции останавливаются; выводится сообщение о демо и будущем email. Создание нового рабочего пространства не выдаёт дополнительные $5. Проверка этого поведения есть в `tests/test_demo_budget.py`; не нужно тратить $5 настоящими вызовами ради теста.

В таблице `demo_accounts` записаны:

- `user_id` — связь с email в `users`;
- `spent_microusd`, `reserved_microusd`, `limit_microusd` — суммы в миллионных долях доллара;
- `limit_reached_at` — дата достижения лимита;
- `launch_email_requested_at` — отметка будущего уведомления;
- `notification_reason` — `demo_budget_exhausted` либо `launch_requested`;
- `launch_email_sent_at` — пока пусто.

Пользователь может нажать `Email me at launch` и до исчерпания лимита. Для оператора подготовлен экспорт только подтверждённых адресов с запросом уведомления, которым письмо ещё не отмечено отправленным:

```bash
python -m scripts.demo_waitlist --output var/launch-notifications.csv
```

Команда создаёт новый локальный CSV и **не отправляет письма**. Файл содержит персональные данные; хранить его нужно в закрытом операторском окружении, вне Git. После будущей реальной отправки отметь `launch_email_sent_at` в рамках учёта рассылки. Не выставляй дату отправки заранее.

Настройка Qdrant и перенос старых embeddings без новых вызовов OpenAI: [qdrant.ru.md](qdrant.ru.md).
